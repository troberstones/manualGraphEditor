# Manual Graph Editor — Project Summary

A visual node-based scene composition tool for building and exporting renderable scenes in [Moonray](https://github.com/dreamworksanimation/openmoonray) (DreamWorks' open-source rendering engine). Users wire together RDL2 (Render Description Language 2) objects — geometry, materials, lights, shaders — in a canvas-based node graph, then export to `.rdla` / `.rdl2` files for rendering.

## How to Run

```bash
# Start the Python backend (port 8011)
./startHost.sh

# Open the app
open http://localhost:8011

# Start Moonray renderer (separate process)
./startMoonray.sh
```

No build step. The frontend is vanilla JS served directly by the Python HTTP server.

## Architecture

**Frontend** — Vanilla JavaScript (no framework), HTML5 Canvas 2D, loaded via `<script>` tags in dependency order.

**Backend** — `host.py`, a Python `http.server` on port 8011. Handles file serving, JSON persistence, and RDL/RDLA generation. Uses Pixar USD (`pxr`) for geometry prim expansion.

**Schema** — `rdl2Objects.json` (~1.4 MB) defines all available RDL2 scene classes. Generated by `prepRdl2Json.sh` from a live Moonray install.

| File | Role |

| File | Role |
|------|------|

## Key Concepts

- **RdlObject** — a node in the graph. Has a `type` (from `rdl2Objects.json`), `name`, canvas position, and `attributes` map.
- **NodeConnection** — a directed edge between an output port of one `RdlObject` and an input attribute of another.
- **Layer stack** — a Substance-style layer system for procedural material composition. Managed by `layerEditor.js`.
- **Delta export** — only changed/new objects are written to `delta.rdla` on each render, enabling iterative live-render workflows.
- **USD prim expansion** — a geometry node with a wildcard prim path (e.g. `/scene/geo/*`) is expanded server-side using `pxr.Usd` into one node per matched prim.

## Data Flow

```
User action (canvas / sidebar)
  → interaction.js / ui-properties.js
    → scene.js (mutate listOfObjects)
      → renderer.js (redraw canvas)
        → io.js (persist to localStorage)

Save/Export:
  → io.js → POST /saveSceneAsJson or /writeRdla2File
    → host.py (topo-sort, RDL serialization, USD expansion)
      → .rdla / .rdl2 files on disk
```

## File I/O Endpoints (host.py)

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/saveSceneAsJson` | POST | Write scene JSON to a file path |
| `/loadSceneFromJson` | POST | Read scene JSON from a file path |
| `/writeRdla2File` | POST | Generate and write `.rdla` + `.rdl2` render files |
